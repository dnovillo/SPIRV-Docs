Terms

Image: What has been traditionally described as a texture or an image in various APIs. SPIR-V has this single name for these. It does not include any information about how to access, filter, or sample the image.

Sampler: Settings that describe how to access, filter, or sample an image, or an opaque reference to such settings. A sampler does not include an image.

Capabilities

Add a new LiteralSampler capability. The intention is that it is core for OpenCL but not for Vulkan (an extension would need to say it is supported).

Types

OpTypeSampler: Change OpTypeFilter → OpTypeSampler. Still an abstract type. OpVariable of this type in a uniform storage class can be bound to an API-provided sampler. OpConstantSampler of this type can declare a literal sampler.

OpTypeImage: Change OpTypeSampler → OpTypeImage. Inside, it has

  • Element Type (float/int/void) returned by sampling and fetch operations. Allow OpTypeVoid, to support OpenCL model of not knowing the sampled type at compile time.

  • Dim (2D, 3D, buffer, …)

  • Depth: whether it is a depth image (about the image, not about the operation)

  • Arrayed

  • MS

  • Sampled: whether or not this image will be accessed in combination with a sampler, or whether this is not even known statically.

  • Format: See new table above, non-Unknown only required if opImageRead will be done (not required for fetch texel).

An OpVariable of type OpTypeImage in a uniform storage class can be bound to an API-provided image.

OpTypeSampledImage: Add OpTypeSampledImage. An abstract type. OpVariable of this type in a uniform storage class can be bound to API-provided combined image and sampler. OpSampledImage of this type can build a combined image and sampler.

Operations

OpConstantSampler: Change the description of OpConstantSampler to say its result type is OpTypeSampler. This will be marked with the LiteralSampler capability. Also, consider bringing in the tables into the opcode description; they are simple, used only for this opcode, and need the same capability as OpConstantSampler. OpenCL literals say things about clamp/repeat/etc., nearest/linear, and parametric/non-parametric. Vulkan might want to add LOD min/max, depth comparison state, other?

OpSampledImage: Change OpSampler → OpSampledImage. Result type is OpTypeSampledImage. Inside it has

  • Image of type OpTypeImage whose Sampled is true

  • Sampler of type OpTypeSampler

OpImageSampleXXX: Change OpTextureSampleXXX → OpImageSampleXXX. These operate only on images of type OpTypeSampledImage. They do filtered accesses, based on the sampler. If Element Type of the image is OpTypeVoid, then Result Type dictates the result type. Otherwise, Result Type is validated against Element Type.

OpImageTexelFetchXXX: Change OpTextureTexelFetchXXX → OpImageTexelFetchXXX. These operate only on images of type OpTypeSampledImage. They do non-filtered accesses, and ignore the sampler. They do filtered accesses, based on the sampler. If Element Type of the image is OpTypeVoid, then Result Type dictates the result type. Otherwise, Result Type is validated against Element Type.

OpImageQueryXXX: Use OpImageQueryXXX instructions to query Size, Lod, Samples, and Levels. These operate on anything whose type is OpTypeImage or OpTypeSampledImage. Overloading okay?

New image operations:

Add OpImageRead. Like GLSL imageLoad(). It operates of things of type OpTypeImage whose Sampled is false. It requires that the Format be something other than None.

Add OpImageWrite. Like GLSL imageStore(). It operates of things of type OpTypeImage whose Sampled is false.

(See issues.) Add OpImageQueryDim to get the dimensionality. Needs Kernel capabability.

Add OpImageQueryFormat to return an Image Format (see new table above). Needs Kernel capabability.

Add OpImageQueryOrder to get the Channel Order. Needs Kernel capabability.

Making explicit Dref comparisons part of the operation

Background notes

  • There are currently 13 true sampling instructions (ignoring texel fetch) plus 3 gather instructions.

  • 1 explicit Dref comparison instruction already exists, because Dref is an extra operand (didn’t fit in the vec4).

  • Need to change the 3 XXXGatherXXX instructions to also use an extra-operand Dref (instead of being part of the coordinate). Note this makes them match GLSL, which also uses an extra scalar for Dref.

  • So at least these 4 instructions will have an independent scalar Dref.

  • That leaves 8 sampling instructions currently taking Dref as part of the coordinate. 3 have an optional argument (Bias), the other 5 do not. (But, overall, 4 instructions have optional Bias.)

Dref Proposal

Main proposal:

  • Make all Dref be independent scalars, not a component in a coordinate.

  • Stop having optional Bias operands. Instead, add 4 more instructions that make bias explicit ("Bias" is in the name of the opcode).

  • Make the Dref be an optional argument on the 11 instructions that can use it (8 sampling and 3 XXXGatherXXX)

    • main alternative: add 11 instructions to make Dref explicit
